# ChiliCraft 统一指令与分类导航菜单设计

- 日期：2026-09-28
- 状态：已获用户确认，待实施计划
- 目标环境：Paper 1.21.1、Java 21、Gradle Kotlin DSL
- 范围：现有 7 个模块的统一指令入口、分类导航菜单、权限与生命周期注册；为后续 5 个规划模块预留灰显入口

## 1. 背景与决策

当前各模块分别提供 `/cc`、`/demon`、`/soul`、`/martial`、`/adventure`、`/ccseason` 等入口，命名、参数和 Tab 补全风格不统一。`cc-core` 已有主菜单，但只包含档案与模式切换；架构文档声明的 `/cc menu` 尚未实现，顶层 `/menu` 不存在。

定稿决策：

1. 采用“核心菜单入口与指令路由注册表”。
2. `cc-core` 只定义公开注册契约和统一界面，不直接依赖附属模块实现。
3. 附属模块启用时注册入口，禁用时注销；模块之间继续保持零编译期依赖。
4. `/menu`、`/cc`、`/cc menu` 打开同一分类导航菜单。
5. 新增 `/cc <模块> [子命令]` 统一入口，原模块命令全部保留并复用同一处理逻辑。
6. 未实现模块灰显预告；管理中心仅对拥有管理权限的玩家显示。

## 2. 公开 API 与组件边界

### 2.1 菜单入口注册表

`cc-core` 在公开 API 中提供菜单入口注册、注销和查询能力。注册描述至少包含：

- 模块 ID 与显示名；
- 所属分类；
- 图标 Material；
- 排序值；
- 玩家使用权限；
- 管理权限（可选）；
- 简短说明；
- 打开模块页面的主线程回调；
- 模块是否可用。

注册表不保存 `Player`，只保存不可变描述和回调。重复模块 ID 拒绝注册并给出可读错误。模块禁用时必须按模块 ID 注销，核心禁用时清空注册表。

### 2.2 统一指令路由

附属模块注册：

- 规范模块 ID；
- 可选别名；
- 实际玩家/管理权限；
- 命令执行回调；
- Tab 补全回调。

`/cc <模块> ...` 由核心完成模块解析和基础权限检查，再将剩余参数交给模块现有命令处理器。旧顶层命令与统一路由必须进入同一业务分发方法，不复制玩法逻辑。

### 2.3 生命周期

- onEnable：取得 `ChiliCraftAPI` → 注册配置 → 装配业务 → 注册菜单入口和指令路由 → 订阅事件。
- onDisable：取消任务 → 退订事件 → 注销菜单入口和指令路由 → 清空模块状态。
- `core.reload` 只刷新菜单文案、配置和缓存，不重复注册回调。
- 所有 Inventory 与 Bukkit 玩家操作只在主线程执行。

## 3. 分类导航菜单

### 3.1 主菜单

主菜单为 27 格，固定入口：

| 槽位 | 内容 |
|---:|---|
| 4 | 玩家档案 |
| 10 | 生存冒险 |
| 11 | 成长体系 |
| 12 | 世界生态 |
| 13 | 模式切换 |
| 14 | 社交生活 |
| 15 | 经济服务 |
| 16 | 巡演方街 |
| 21 | 家园 |
| 22 | 帮助中心 |
| 23 | 灵魂余额 |
| 26 | 关闭 |
| 18 或 25 | 管理中心，仅有权限时显示 |

空槽使用统一背景物品。继续使用 `GuiHolder` 和全局 `GuiListener`，禁止依赖标题判断菜单。

### 3.2 模块分类

- 生存冒险：生存、恶魔、冒险；
- 成长体系：灵魂、武学、任务（灰显）；
- 世界生态：季节、世界活动（灰显）；
- 社交生活：休闲（灰显）；
- 经济服务：经济（灰显）；
- 巡演方街：方街（灰显）。

模式切换保持核心现有 Adventure / Cozy 逻辑，不作为附属模块。

### 3.3 分类页

分类页使用 54 格：上部分类说明，中部按排序值展示注册模块；未实现模块显示灰色预告；第 45 格返回、第 49 格帮助、第 53 格关闭。

- 左键：打开模块菜单或状态页；
- 右键：打开该模块指令帮助；
- 已实现但无权限：默认隐藏；
- 已注册但不可用：显示不可用状态，不执行回调；
- 规划模块：点击只提示“开发中”；
- 管理中心：只展示低风险状态、帮助、现有安全重载和已有管理菜单入口。

不提供动态启停插件、卸载模块、热替换 JAR、强制重建世界或清空玩家数据。

## 4. 统一指令规范

### 4.1 全局入口

```text
/menu
/cc
/cc menu
/chilicraft
/cc help [模块]
/cc info
/cc home
/cc sethome
/cc balance
/cc mode <adventure|cozy>
```

兼容规则：原 `/cc soul` 继续查询灵魂余额；`/cc soul menu` 打开灵魂模块；新文档推荐 `/cc balance` 查询余额。

### 4.2 模块入口

```text
/cc <模块> [子命令] [参数...]
```

| 模块 | 统一入口 | 兼容入口 |
|---|---|---|
| 生存 | `/cc survival` | 无 |
| 恶魔 | `/cc demon` | `/demon` |
| 灵魂 | `/cc soul menu` | `/soul` |
| 武学 | `/cc martial` | `/martial` |
| 冒险 | `/cc adventure` | `/adventure` |
| 季节 | `/cc season` | `/season`、`/ccseason` |
| 任务 | `/cc quest` | 规划中 |
| 休闲 | `/cc cozy` | 规划中 |
| 活动 | `/cc events` | 规划中 |
| 经济 | `/cc economy` | 规划中 |
| 方街 | `/cc street` | 规划中 |

不带模块子命令时打开模块菜单；没有独立 GUI 的模块打开只读状态页。未安装规划模块返回开发中提示，而非未知命令。

### 4.3 参数与补全

- 模块 ID、子命令和枚举值统一小写英文；
- 玩家名和配置 ID 保留原始大小写；
- 无效参数必须返回用法和候选；
- 控制台执行玩家专属操作时给出明确反馈；
- Tab 补全按输入前缀、模块可用性和权限过滤；
- 管理子命令不向无权限玩家暴露候选。

## 5. 权限模型

核心权限：

```text
chilicraft.use
chilicraft.menu
chilicraft.home
chilicraft.mode
chilicraft.admin
```

模块新规范：

```text
chilicraft.<module>.use
chilicraft.<module>.admin
```

第一阶段保留现有权限节点，避免破坏已有 LuckPerms 配置。模块注册以现有权限为实际依据；新增规范权限与旧权限任一满足即可。新文档和新功能只使用规范权限名，旧权限暂不删除。

菜单行为：

- 无模块权限时隐藏已实现模块；
- 灰显规划模块对所有有菜单权限的玩家可见；
- 管理中心仅对拥有 `chilicraft.admin` 或任一已注册模块管理权限的玩家显示；
- 统一指令必须重复执行权限校验，不能依赖菜单可见性。

## 6. 现有模块接入

接入顺序：`cc-survival`、`cc-demon`、`cc-soul`、`cc-martial`、`cc-adventure`、`cc-season`。

每个模块必须同步完成：

1. 注册菜单入口；
2. 注册统一命令路由；
3. 将旧命令和统一入口收敛到同一分发方法；
4. 增加规范权限并兼容旧权限；
5. plugin.yml、Tab 补全和帮助文本保持一致；
6. onDisable 注销入口；
7. 配置重载不重复注册。

`cc-survival` 当前无独立菜单，提供只读状态页或分类说明入口，不新增不必要的管理行为。`cc-season` 菜单暴露季节信息、HUD、指南和时钟，不向普通玩家暴露设置季节操作。

## 7. 异常处理与降级

- 重复注册：拒绝并禁用有问题的附属模块，核心继续运行；
- 模块回调异常：捕获、记录模块 ID，并向玩家发送统一失败提示；
- 模块禁用：注销后分类菜单下一次打开不再调用旧回调；
- 无效 Material 或菜单文案：使用核心默认图标和中文兜底文案；
- 菜单打开期间模块被禁用：点击时重新查询注册表，不持有失效模块快照回调；
- 未安装模块：核心只展示静态规划描述，不伪造功能。

## 8. 验收设计

### 8.1 构建与静态检查

- `./gradlew.bat build` 或网络异常时 `./gradlew.bat build --offline` 必须成功；
- Java 21、Paper 1.21.1；
- 不引入新依赖；
- plugin.yml 声明与实际注册一致；
- Java diagnostics 无新增错误。

### 8.2 指令验收

验证 `/menu`、`/cc`、`/cc menu` 打开同一菜单；验证 `/cc help`、全部统一模块入口和全部旧入口。检查新旧行为一致、控制台边界、未知参数反馈、规划模块提示、前缀补全和权限过滤。

### 8.3 GUI 验收

- 分类槽位固定；
- 已启用模块进入正确页面；
- 灰显模块无异常；
- 左键、右键、返回、帮助、关闭正确；
- Shift 点击、数字键、双击和拖拽不能取出菜单物品；
- 普通玩家不显示管理中心，管理员显示；
- 模块禁用后不调用失效回调。

### 8.4 生命周期与线程验收

- 每个模块只注册一次；
- `/cc reload` 不产生重复入口；
- onDisable 完整注销；
- 注册表不长期持有 Player；
- 不新增未取消调度任务；
- 不从异步线程操作 Inventory、世界或玩家状态。

### 8.5 回归验收

- `/cc soul` 继续查询余额；
- 模式、家园、档案和核心重载行为不变；
- 原有模块 GUI 与管理员命令正常；
- `core.reload` 事件正常；
- 模块间零编译期依赖保持；
- `cc-season` ProtocolLib 视觉不受影响。

## 10. 明确不含

- 本轮不实现 `cc-quest`、`cc-cozy`、`cc-events`、`cc-economy`、`cc-street` 的业务逻辑；
- 不移除任何旧指令或旧权限；
- 不提供插件动态加载、卸载或 JAR 热替换；
- 不顺手修复 WorldGuard、EssentialsX、MythicMobs 等第三方兼容问题；
- 不改变现有玩法数值、持久化结构或事件语义。
